部署与管理工具

工具的价值是降低重复劳动，不是替代安全设计。部署前先明确入口、出口、协议、端口和管理边界，再选择核心、面板或脚本。

系统与部署前检查

推荐基础环境

  • Debian 12 或当前受支持版本。
  • Ubuntu 24.04 LTS 或当前受支持的 LTS。
  • 确认服务商控制台、救援模式和回滚方式可用。
uname -a
cat /etc/os-release
ip addr
ip route
ss -lntup
timedatectl status

时间同步直接影响 TLS、REALITY 和证书签发。涉及内核、网络或 SSH 的操作，应保留现有会话并准备回滚。

系统更新与基础工具

apt update
apt upgrade -y
apt install -y curl ca-certificates unzip jq ufw fail2ban

生产环境的核心和面板应从官方项目、软件包或可信容器镜像获得，并在升级前阅读变更说明。不要长期保存未经复核的一键命令。

代理核心与管理面板

工具定位适合注意
Xray-core多协议代理核心VLESS、Trojan、多入站/出站、链式代理配置需匹配具体传输和版本
sing-box通用代理平台多协议、TUN、DNS、路由和链式出站升级前阅读迁移说明
Mihomo规则与策略核心Clash 兼容配置、代理组、TUN、DNS字段以当前官方文档为准

3x-ui

3x-ui 是基于 Xray-core 的第三方面板，适合管理入站、用户、流量和订阅。请以官方项目当前 README 为准。

  • 管理端口只允许可信 IP，或通过 SSH 隧道访问。
  • 修改默认账户、密码、路径和端口，启用 HTTPS。
  • 定期备份数据库和证书，升级前阅读 release notes。
  • 面板权限与系统 root 权限分离，面板不应直接暴露公网。

Marzban

Marzban 面向多用户、API、生命周期、订阅和多节点管理。部署前核对官方项目推荐的数据库、反向代理、备份与升级流程。

不作为新部署首选的项目

项目处理方式
Qv2ray已停止维护，仅用于理解历史生态
NekoRay/NekoBox for PC 原仓库已归档并明确停止维护，使用前核对当前维护来源
Trojan-Go作为历史兼容背景，现代部署优先用活跃核心中的 Trojan 实现
V2Board偏商业订阅管理，公开仓库活跃度和安全性需单独评估
未核实的一键脚本与面板不透明的来源、权限和更新机制不适合生产环境

证书、SSH 与运维工具

标准 TLS 方案需要正确域名、ACME 验证路径、可用的 443 端口、自动续签和服务重载。使用 acme.sh 或 Let's Encrypt 时以当前官方文档为准。

Fail2ban 与 vnStat

apt install -y fail2ban vnstat
systemctl enable --now fail2ban
fail2ban-client status
systemctl enable --now vnstat
vnstat
vnstat --iflist

Fail2ban 只降低暴力尝试风险，不能替代密钥认证。新版 vnStat 通常会自动发现接口，不要依赖旧版初始化命令。

备份原则

  • 备份代理配置、面板数据库、TLS 证书与 ACME 账户。
  • 备份 WireGuard 密钥、防火墙规则和 systemd 覆盖配置。
  • 备份文件含凭据，必须加密并限制权限。
  • 升级前记录版本并保留可回滚副本，定期做恢复演练。

面板是便利工具，不是安全边界。真正的安全边界来自 SSH 密钥、来源限制、防火墙、最小权限、备份和持续更新。
