常见问题与排障

排障不是反复更换协议，而是沿着数据路径定位故障发生在哪一段：解析、监听、握手、路由、下一跳、最终出口或系统旁路。

方案选择

第一次部署推荐什么方案？

先选一个仍在维护的核心和客户端，使用可验证的单节点方案：VLESS + REALITY，或 Trojan/VLESS + 标准 TLS。UDP 可用且丢包明显时，再测试 Hysteria2，并保留 TCP 备用节点。多用户管理才考虑 3x-ui 或 Marzban。

需要域名吗？

方案域名/证书
VLESS + REALITY不要求服务端持有传统公有证书，但参数和目标站必须正确
VLESS/Trojan + 标准 TLS需要正确域名、证书、SNI 和续签机制
Shadowsocks 2022不需要 TLS 证书，但密钥格式必须符合实现要求
Hysteria2通常需要证书或受信任配置，并依赖 UDP

Reality、Trojan 和 Hysteria2 谁更好？

没有固定答案。Reality 和标准 TLS 主要建立在 TCP/TLS 语义上，Hysteria2 建立在 UDP/QUIC 上。实际结果由网络是否允许 UDP、线路拥塞、丢包、MTU、客户端版本和目标兼容性共同决定。

连接问题

无法连接服务器怎么办？

  1. 确认 DNS 是否正确解析。
  2. 在服务端检查监听：ss -lntup。
  3. 同时检查云安全组和系统防火墙。
  4. 核对 TCP/UDP 类型与端口。
  5. 核对时间、证书、SNI、UUID、密钥、shortId 和客户端指纹。
  6. 查看服务日志，确认是监听、握手、路由还是目标连接失败。
systemctl --failed
systemctl status xray
journalctl -u xray --since today
ss -lntup

连接后很慢怎么办？

现象或可能原因验证与处理
线路拥塞分别从入口机和落地机测试延迟、路由和出口，不要先改协议
服务器资源或带宽不足检查 CPU、内存、连接数、流量和服务商限制
UDP 受限对 Hysteria2/TUIC 测试 UDP 端口，并保留 TCP 节点
MTU 或 IPv6 异常分别测试 IPv4、IPv6 和 MTU，检查是否旁路
TCP 拥塞控制先检查内核是否支持 BBR；BBR 不影响 UDP

频繁断线怎么办？

先区分是入口连接断、链式下一跳断、UDP 被限速，还是目标服务主动断开。检查客户端和服务端日志、连接数、时间同步、服务商端口限制和路由环路。

家宽中转与 DNS

如何确认家宽出口真的生效？

机房出口和家宽出口分别运行 curl -4 https://ipinfo.io 与 curl -6 https://ipinfo.io，再单独验证 DNS、WebRTC 和应用自带 DoH。客户端显示“Home”不等于最终连接真的走了家宽。

家宽后端需要暴露给公网吗？

不应开放给任意公网来源。WireGuard 或代理后端都应使用认证和加密，并在防火墙上只允许机房 VPS 的固定来源。家宽 VDS 的真实地址不放入公开订阅。

DoH 能防止 DNS 泄露吗？

不能自动保证。DoH/DoT 只加密到 DNS 服务器的查询，最终出口仍取决于代理核心、路由、引导解析和 TUN 设置。需要结合查询日志、系统连接或抓包验证。

主机安全

面板要不要直接暴露公网？

不建议。优先通过可信来源 IP、SSH 隧道、私网或 WireGuard 访问，并修改默认账户、密码、路径和端口。面板不替代防火墙、SSH 密钥、备份和更新策略。

SSH 无法登录怎么办？

  • 不要立即关闭仍在线的旧会话。
  • 检查当前端口、密钥、sshd -t 和防火墙。
  • 确认是否被 Fail2ban 封禁。
  • 使用服务商 Console 或救援模式修复。

怀疑服务器被入侵怎么办？

  1. 通过服务商控制台隔离网络，保留必要证据。
  2. 备份重要数据和日志，但不要把可疑系统当作可信环境。
  3. 重新安装受支持系统并轮换所有凭据、密钥和证书。
  4. 分析入口原因，再恢复最小服务。

维护与备份

  • 记录 Xray、sing-box、Mihomo、面板和系统版本。
  • 定期检查证书有效期、磁盘、内存、连接数、日志轮转和防火墙规则。
  • 备份配置、面板数据库、证书、ACME 账户、WireGuard 密钥和 systemd 覆盖配置。
  • 备份加密、限制权限，并做恢复演练。

排障时可以临时提高日志级别，但日志可能包含客户端 IP、目标域名、订阅和用户标识，问题解决后要恢复级别并按策略清理。

官方文档优先

协议字段和客户端支持会随版本变化。遇到配置问题时，优先查对应核心、客户端或面板的官方 README、文档和 release notes；不要把多年前的教程当成当前规范。
