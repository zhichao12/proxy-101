协议、核心与客户端

协议描述通信方式，代理核心负责实现协议、传输、路由和 DNS，图形客户端负责配置和操作。三者不是同一层，比较方案时必须先分清职责。

分类与职责

类别常见项目解决的问题
基础代理协议HTTP、SOCKS4/4a/5定义应用如何把请求交给代理
加密代理协议Shadowsocks、Trojan、VMess、VLESS在代理连接中提供认证、加密或特定传输语义
UDP/QUIC 类协议Hysteria2、TUIC在 UDP 可用时处理高延迟或丢包链路
代理核心Xray-core、V2Ray、sing-box、Mihomo组合入站、出站、路由、DNS、TUN 等能力
图形客户端v2rayN、Clash Verge Rev、v2rayNG、FlClash、Shadowrocket导入节点、切换策略并接管系统流量
管理面板3x-ui、Marzban管理用户、入站、订阅和流量，不等于代理协议

现代方案对比

方案传输基础证书要求适合限制
VLESS + REALITYTCP/TLS 类握手不要求服务端持有传统公有证书直连入口、需要灵活配置的场景参数多，目标站与客户端兼容性必须验证
VLESS + TLSTCP + TLS域名和证书标准 TLS、易理解和维护需要维护域名、证书和 Web 服务
Trojan + TLSTCP + TLS域名和证书标准 TLS 和广泛客户端支持证书、SNI 和服务端配置必须正确
Hysteria2UDP + QUIC通常需要证书或受信任配置UDP 可用且高延迟或丢包明显的网络UDP 可能被限速或阻断，MTU 需测试
TUICUDP + QUIC依实现和配置而定低延迟和多路复用场景客户端兼容性与 UDP 可用性需确认
Shadowsocks 2022TCP/UDP不需要 TLS 证书轻量内部中转或受控环境双方必须支持同一加密方式和密钥格式
WireGuardUDP 三层隧道不需要 TLS 证书服务器间长期固定隧道不自动解决路由、NAT、DNS 和访问控制

不存在对所有网络都“抗封锁最强”或固定提速的协议。线路质量、UDP 可用性、MTU、客户端版本和服务商策略都会改变结果，至少准备一个不同传输基础的备用方案。

Xray-core 与 REALITY

Xray-core 是多协议代理核心，不是单一协议。是否使用 TLS、REALITY、WebSocket 或 gRPC，取决于具体入站、出站和传输配置。

  • 适合 VLESS + REALITY 直连入口。
  • 可提供 VLESS/Trojan + TLS、多入站、多出站和受控链式代理。
  • 官方项目：Xray-core；文档：xtls.github.io。

REALITY 配置边界

REALITY 是 Xray 的 TLS 类认证与握手机制，不等同于动态端口，也不是随意填写一个知名网站就能完成伪装。

参数为什么要核对
服务端私钥与客户端公钥决定认证是否能完成
shortId、VLESS 用户 ID必须与对端配置一致
serverName、目标地址和端口受目标站可达性、TLS 行为和兼容性影响
客户端指纹、Vision 流控版本和实现必须支持，不能只复制旧配置

sing-box、Mihomo 与其他核心

sing-box

sing-box 是通用代理平台，适合多协议、TUN、DNS、路由和链式出站。配置升级前阅读官方迁移说明，旧字段和实验性功能的兼容策略会随版本变化。

项目：github.com/SagerNet/sing-box，文档：sing-box.sagernet.org。

Mihomo

Mihomo 是原 Clash.Meta 项目演进后的名称，适合规则分流、订阅、代理组、TUN 和 DNS 管理。文档中应使用“Mihomo”，仅在解释历史名称时写“Mihomo（原 Clash.Meta）”。

项目：github.com/MetaCubeX/mihomo，文档：wiki.metacubex.one。

Hysteria2

Hysteria2 基于 QUIC/UDP，在高延迟或一定丢包网络中可能优于传统 TCP，但不能用固定速度或百分比描述性能。部署前检查 UDP、防火墙、安全组、MTU、证书和持续 UDP 流量限制。salamander 混淆需要两端参数一致。

项目：github.com/apernet/hysteria，文档：v2.hysteria.network。

Shadowsocks 与 Trojan

Shadowsocks 优先使用现代 AEAD 或双方均支持的 Shadowsocks 2022 加密方式，例如 2022-blake3-aes-128-gcm、2022-blake3-aes-256-gcm、chacha20-ietf-poly1305。2022 方案有明确的主密钥格式，不能把普通口令直接当作 Base64 主密钥。

现代 Trojan 部署优先使用 Xray-core 或 sing-box 的实现。Trojan-Go 只作为历史兼容背景，不作为新部署首选。标准 TLS 需要正确域名、有效完整证书链、SNI、安全 TLS 配置以及合理的回落或 Web 服务。

WireGuard

WireGuard 只提供加密三层隧道。服务器间长期链路通常适合它；若只需转发某个代理出站，Xray 或 sing-box 链式出站可能更容易按策略控制。

按场景选择

场景建议
新建直连入口VLESS + REALITY，或 Trojan/VLESS + 标准 TLS
UDP 可用且线路丢包明显测试 Hysteria2，并保留 TCP 备用节点
服务器间长期中转WireGuard，或受控的 Xray/sing-box 链式出站
轻量内部中转Shadowsocks 2022 或带认证 SOCKS5，并限制来源 IP
复杂客户端分流Mihomo 或 sing-box
多用户管理3x-ui 或 Marzban；管理面板不应直接暴露公网

选择顺序应是：先确认目标场景和线路，再确认客户端支持，最后选择核心与协议。协议不能修复带宽不足、严重拥塞或错误的路由设计。
