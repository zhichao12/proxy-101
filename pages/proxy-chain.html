家宽中转与链式代理

中转的关键不是增加跳数，而是把“客户端接入”“线路转发”和“最终出口”拆成可验证的角色。链路越长，延迟、成本、故障点和日志边界也越多。

目标架构

客户端 → 机房 VPS 入口 → 家宽 VDS → 家宽 IP → 互联网

客户端可以同时保留两个出口：

IDC-机房出口：客户端 → 机房 VPS → 互联网
Home-家宽出口：客户端 → 机房 VPS → 家宽 VDS → 互联网

家宽 VDS 的真实地址不写入客户端订阅、截图、公开日志或公开文档。入口、后端和最终出口要分别测试，不能只看客户端“已连接”。

先核验住宅属性

云服务器通常属于数据中心 IP。不要因为服务商名称或套餐宣传就把 AWS Lightsail 或其他云主机直接认定为家宽。

  • 综合 ASN 与 WHOIS。
  • 核对服务商明确说明。
  • 参考多个 IP 分类数据库。
  • 观察目标服务的实际识别结果。
  • 确认是否是共享、广播或代理出口。

分类数据库可能冲突或滞后；住宅属性也不保证账号安全、服务可用或不受限制。

三种中转方案

WireGuard：长期固定隧道

客户端 → 机房 VPS → WireGuard → 家宽 VDS → 互联网

需要配置双端密钥、隧道地址、IP 转发、NAT、策略路由、DNS 路由、MTU 和访问控制。优点是性能和结构清晰；缺点是路由与 DNS 设计复杂。

Xray 或 sing-box 链式出站

客户端 → 机房入口 → 家宽出站 → 家宽 VDS 入站 → 最终出口
  • 可按用户、域名或策略组选择出口。
  • 不必把全部系统流量送入隧道。
  • 家宽入站只允许机房 VPS 来源，使用独立凭据和端口。
  • 明确域名由哪一端解析，记录入口、出站和落地标签，避免路由环路。

带认证的 SOCKS5：快速验证

不建议将无加密 SOCKS5 暴露给公网。至少启用用户名和强密码、防火墙来源限制，并确认支持远程域名解析。服务器间优先叠加 WireGuard 或其他加密链路。socks5h:// 在部分工具中表示由代理端解析域名，具体行为以客户端和库文档为准。

家宽 VDS 防火墙

假设机房 VPS 地址为 1.2.3.4，家宽后端 TCP 端口为 23147：

ufw default deny incoming
ufw default allow outgoing
ufw allow from 1.2.3.4 to any port 23147 proto tcp
ufw enable

WireGuard 使用 UDP 时：

ufw allow from 1.2.3.4 to any port 51820 proto udp

随机高位端口只能减少扫描噪声，核心安全措施仍是来源限制、认证、加密和及时更新。

验证链路

选择机房节点和家宽节点后分别检查：

curl -4 https://ipinfo.io
curl -6 https://ipinfo.io
  1. 客户端能否连接机房 VPS。
  2. 机房 VPS 能否到达家宽 VDS 后端端口。
  3. 云安全组与 UFW 是否允许正确来源和协议。
  4. 家宽后端服务是否监听正确地址。
  5. 出站凭据、端口和传输参数是否一致。
  6. 路由规则是否真正选中家宽出站。
  7. 家宽 VDS 本机能否访问互联网。
  8. IPv4、IPv6、DNS 和 MTU 是否分别正常。

验收标准是：IPv4 出口符合预期，IPv6 不旁路，DNS 走指定路径，未经授权的来源无法直达家宽后端，订阅中不出现家宽 VDS 公网地址。

为什么不应盲目增加跳数

可能收益对应代价
补足入口到落地的线路质量增加 RTT 和带宽瓶颈
隐藏或保护最终出口地址入口和后端都必须做来源控制
按规则选择不同出口路由、DNS 和日志更难排查
提供故障隔离节点越多，单点故障越多

如果说不清楚是在补线路、保护落地还是做出口分流，通常应先把单节点跑通，再增加中转角色。

排障顺序

  1. 客户端到机房入口。
  2. 机房入口到家宽后端端口。
  3. 安全组、UFW 和协议类型。
  4. 后端监听地址。
  5. 出站认证与传输参数。
  6. 路由是否选中家宽出站。
  7. 家宽本机互联网、IPv4、IPv6、DNS 和 MTU。
