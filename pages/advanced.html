进阶优化与维护

性能优化必须先定位瓶颈：TCP 拥塞控制、线路质量、UDP 可用性、DNS、MTU、路由和服务端资源分别影响不同阶段。没有测量就直接改参数，通常只会增加变量。

BBR：只针对 TCP

现代 Debian/Ubuntu 内核通常已经包含 BBR。先检查可用算法，不要重复追加配置。BBR 影响 TCP 拥塞控制，不会直接加速 Hysteria2 或 WireGuard 的 UDP 流量。

sysctl net.ipv4.tcp_congestion_control
sysctl net.ipv4.tcp_available_congestion_control

需要启用时创建独立配置：

cat >/etc/sysctl.d/99-bbr.conf <<'EOF'
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr
EOF
sysctl --system
sysctl net.ipv4.tcp_congestion_control

CDN 的边界

Cloudflare 普通橙云主要代理受支持端口上的 HTTP/HTTPS 流量，不是任意 TCP/UDP 转发器。

通常可能适配不能直接套用
WebSocket over TLS；满足 CDN 条件的 HTTP/2 或 gRPC；普通网站和反向代理VLESS + REALITY；任意裸 TCP；WireGuard；Hysteria2；任意 UDP 服务

使用 CDN 前核对当前服务条款、端口支持、WebSocket/gRPC 支持和回源设置。橙云不保证源站 IP 不会通过历史 DNS、证书透明度、其他子域名或主动探测泄露。

源站保护

  • 源站防火墙只允许官方 CDN 回源 IP，并自动维护 IP 段。
  • 管理面板和 SSH 不通过同一公开反向代理路径暴露。
  • 不在公开 DNS、日志、截图或订阅中泄露源站地址。
  • 定期检查历史 DNS、证书记录和旁路端口。

DNS 与泄露防护

选择家宽出口时，目标不是“打开 DoH”这么简单，而是分别验证访问流量、DNS 查询和客户端配置：

访问流量 → 家宽出口
DNS 查询 → 指定代理路径或家宽链路
客户端配置 → 不包含家宽 VDS 公网地址

DoH/DoT 只加密客户端到 DNS 服务器的查询，不自动保证 DNS 使用家宽出口。实际出口由代理核心、路由规则和引导解析共同决定。

Mihomo 结构示例

dns:
  enable: true
  listen: 127.0.0.1:1053
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  nameserver:
    - https://cloudflare-dns.com/dns-query
    - https://dns.google/dns-query

listen: 127.0.0.1 仅服务本机。只有明确需要为局域网提供 DNS 并已配置防火墙时，才监听 0.0.0.0。

TUN 与 DNS 劫持

tun:
  enable: true
  stack: system
  auto-route: true
  dns-hijack:
    - any:53
  • 检查系统 DNS 是否指向内核监听地址。
  • 检查应用自带 DoH 是否绕过系统设置。
  • 检查 IPv6 DNS 是否仍然直连。
  • 为局域网和私有域名保留必要例外。

引导解析与链式出站

DoH 服务器本身是域名时，需要先解析其地址。应区分默认 DNS、代理节点域名、DoH/DoT 服务器引导解析、直连域名 DNS 和代理域名 DNS。

domainStrategy: AsIs 只是尽量保留域名，不保证最终由家宽 VDS 解析。最终行为还取决于应用传入域名还是 IP、中间协议是否传递域名、下一跳处理方式、路由是否提前解析以及最终出站和系统 DNS。需要通过查询日志、抓包或专用测试验证。

WireGuard DNS

家宽策略流量 → WireGuard
对应 DNS 流量 → WireGuard 或指定代理 DNS

只把目标网站 IP 路由进 WireGuard，而 DNS 仍从机房或本地发出，会造成出口不一致。

分流与出口选择

proxy-groups:
  - name: 出口选择
    type: select
    proxies:
      - IDC-机房出口
      - Home-家宽出口
  • 默认使用机房出口，减少家宽链路负载。
  • 只有明确需要住宅网络环境的服务才使用家宽出口。
  • 登录、支付和账号敏感服务尽量保持出口地区与 IP 稳定。
  • 同一会话不要频繁切换国家、ASN 或住宅/机房属性。
  • 先处理私网、局域网和必要直连，再处理代理服务。
  • 规则更新后检查是否误伤 DNS、NTP、软件更新和服务器管理流量。

节点名称应表达实际出口，不要把入口服务器位置误写成最终出口位置。

网络测试与排查

ping -c 4 目标地址
tracepath 目标地址
curl -4 https://ipinfo.io
curl -6 https://ipinfo.io
ss -s
  1. DNS 是否正确解析。
  2. 服务是否监听预期地址和端口。
  3. 云安全组与系统防火墙是否同时放行。
  4. TCP、UDP 类型是否匹配。
  5. 客户端与服务器时间是否正确。
  6. 证书、SNI、UUID、密钥和 shortId 是否一致。
  7. MTU、IPv6 和策略路由是否引发异常。
  8. 服务商是否限制端口、代理或持续 UDP。

排障时临时提高日志级别，解决后恢复；日志中的客户端 IP、目标域名、用户标识和订阅信息都应按敏感数据处理。

监控与维护

服务状态

systemctl --failed
systemctl status xray
journalctl -u xray --since today
ss -lntup

服务名按实际安装方式调整。

流量监控

apt install -y vnstat
systemctl enable --now vnstat
vnstat
ip link
vnstat --iflist

备份示例

install -d -m 700 /root/backups
tar -czf /root/backups/proxy-backup.tar.gz /usr/local/etc/xray /etc/wireguard /etc/ufw 2>/dev/null

备份前确认目录存在；恢复演练比只生成备份更重要。实际环境应使用带时间戳且权限受限的备份命名。

定期检查

  • 操作系统安全更新。
  • Xray、sing-box、Mihomo 和面板版本。
  • 证书剩余有效期、磁盘、内存、连接数和日志轮转。
  • 防火墙规则及订阅是否泄露敏感地址。
  • 家宽出口 ASN 与分类是否变化。
  • IPv6 是否意外形成旁路出口。
